# 구매 결정과 견적 요청

첫 화면의 주 행동은 BOM 견적 요청, 보조 행동은 특수요건 확인이다. 16초 회사 소개는 소리 없이 자동 재생되며, BOM 검토 → 특수요건 → 공급 확인 → 견적·C&D 메시지를 영상 시간에 맞춰 보여준다. 모바일은 작은 MP4만 받는다. 화면 밖·숨겨진 탭에서는 멈추며, 움직임 줄이기/데이터 절약 설정은 정지 이미지와 회사 설명을 먼저 표시한다. 별도의 기술 상세 뷰어는 사용자가 선택할 때만 원본 42초 영상 파일을 받는다. 영상은 실제 조립 검증·토크 계산·시공 인증·시험 수치가 아니다.

주력 품목은 편집상 검토 우선순위이며 공급 실적·재고를 주장하지 않는다. 카탈로그 A/B/C 구분과 범용 주력 목록을 이용해 조건부/원문 검토 범위를 표시한다. 제품별 버튼은 품목 식별자를 구매 체크리스트에 연결한다. 모든 품목의 공급 가능 여부는 별도로 확인한다.

구매 경로는 6단계 질문을 제공한다. BOM 줄 번호와 확인 조건은 현재 페이지의 메모리에만 저장한다. 새로고침하면 사라진다. 여러 품목은 줄별 체크리스트를 내려받는다. 원본 BOM과 요청서 엑셀/JSON은 수정하지 않는다. 체크리스트를 별도로 첨부하며, 메일 본문에는 확인 질문을 포함한다. 긴 메일의 축약 본문에도 별첨 안내를 남긴다. 알 수 없는 값은 미확인으로 남기며 값·납기·문서 제공을 확정하지 않는다.

라이브러리의 2026-10은 기존 일괄 검토월이며 개별 검토일은 미기록이다. 발행 기관 링크는 공식 검색·안내 페이지이고 개별 수치의 검증 원문 링크가 아니다. 계약에 쓰는 판본과 상세 값은 정식 원문과 공급처 문서로 확인한다.

신뢰 영역은 공급 절차·문의 범위·사업자등록 정보와 명확히 가상으로 표시한 견적/C&D 예시를 제공한다. 실제 고객 사례·공급 회신·시험 성적은 싣지 않는다.

## 측정 범위

개발자 콘솔 `window.__purchaseMetrics`는 현재 탭의 homeViews, listViews, start(주 CTA/질문→견적), prepared(요청서 보내기 단계), handoff(메일 버튼), checklist(체크리스트 다운로드)를 센다. 개인/기업/BOM/연락처/목적지 값은 기록하지 않으며 외부 전송·영구 저장도 하지 않는다. 반복 클릭을 포함한 진단용 횟수이며 고유 사용자 전환율이 아니다.

메일 버튼 클릭은 앱 실행 시도이며 발송·접수 완료가 아니다. 실제 요청 완료율은 수신 시스템의 유효 신규 요청과 방문 분모를 집계하는 별도 운영 계측이 필요하다. 현재 공개 화면에는 서버 제출 API가 없으므로 접수 성공을 표시하거나 수신율을 만들어 내지 않는다. 이번 검증은 모바일 최초 미디어 다운로드·가로 넘침·6단계 질문·요청서/메일 인계 기능을 측정한다. 실사용자의 완료율 개선은 아직 검증되지 않았다.
