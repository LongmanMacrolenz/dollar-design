# 검색용 페이지 관리

홈과 제품·라이브러리 문서는 자바스크립트 실행 전에도 본문을 제공합니다.
제품 구매 안내는 기존 공개 카탈로그의 품목·표기·주의사항으로 만들며,
재고나 판매 가격을 확정하는 페이지가 아닙니다.

- `catalog.py`: 공개 카탈로그 읽기, 공통 주소·홈 메타정보, 설명문 80자 이내 발췌.
- `product-paths.json`: 카탈로그 ID → 고정 주소. 이름 변경 시에도 주소를 유지합니다.
  새 품목을 추가하면 중복되지 않는 경로를 함께 넣습니다. 경로를 바꿔야 하면
  기존 주소의 영구 리디렉션과 사이트맵·링크 변경을 같은 작업에 포함합니다.
- `build_products.py`: 제품별 구매 안내와 제품군·전체 목록.
- `build_en.py`: 영문 페이지 `docs/en/index.html`(대표 요청 2026-11-11). 대상은 한국에 있는 외국계 공장·플랜트·EPC 현장의 영어 사용 엔지니어·구매 담당이며 해외 판매 페이지가 아닙니다: 납품은 국내, 견적·세금계산서는 원화. 사이트에 있는 사실만 영어로 옮기고(회신 영업일·연락처는 `page.html`에서 읽음), 메일 앱을 여는 링크는 두지 않습니다. 문의 집계에는 `en`으로 잡힙니다.
- `build_tables.py`: 규격표. 품목별 치수표 `docs/tables/<경로>`와 모음 `docs/tables/`(대표 요청 2026-11-10). 주소는 `product-paths.json`의 경로를 그대로 씁니다.
  - **올리는 표는 근거 기록이 저장소에 있는 것만입니다**(`catalog.py` `table_data`): `tools/t2/records/<id>.json` 기록이 있는 T2 표와, 값·출처 주석이 `app/base.html`의 `const DIM`에 있는 미터 핵심 품목(`TABLE_CORE`). 카탈로그에 표가 있어도 기록이 없으면(표시 없는 "원문 대조 행" 표, 기록 없는 T2 표) 올리지 않습니다. 근거를 다시 확인해 기록을 남긴 뒤에 더합니다.
  - 표마다 보이는 자리에 `치수 근거 {규격} · {대조 방법} · 범위 · 단위`를 적습니다. T2는 `app/SOURCE_RULE.md`의 문구 그대로입니다. 값을 새로 넣거나 고치지 않고, 출처 사이트·회사 이름을 쓰지 않습니다. 규격서 원문의 표를 옮기는 것이 아니라 값과 규격 번호만 우리 양식으로 정리합니다.
  - 표 자체는 규격표 페이지 한 곳에만 둡니다. 제품 안내·라이브러리 문서는 링크로 잇습니다(반나사 육각볼트는 온나사 표를 봅니다: `TABLE_ALIAS`).
  - `tools/check_search.py` `check_tables`가 대상 목록·근거 문구·칸 값·링크·출처 이름 없음을 확인합니다.
- `build_products.py`의 `SEARCH_META`: 서치어드바이저 검색어를 보고 제목·설명(80자 이내)·"다른 이름·검색어"를
  손본 품목만 적습니다. 값은 카탈로그의 품목명·`kw` 별칭·안내 문구에서만 가져옵니다. 없는 품목은 공통 양식을 씁니다.
- 정적 페이지의 끝(꼬리말 앞)에는 볼트노트 띠(`build_lib.py` `brand_strip`)가 붙습니다: 「볼트는, 볼트노트.」, 리드 한 줄, 「BOM·RFQ 보내기」(`/#list`)와 「카카오톡으로 문의」(채널 주소가 있을 때만). 검색으로 들어온 방문자는 홈을 보지 않기 때문입니다. 문구는 홈과 같은 것만 쓰고(`catalog.py` `brand_copy`), 재고·가격·납기를 적지 않습니다. `check_search.py`가 모든 정적 페이지에 두 링크가 있는지 봅니다.
- `build_lib.py` `not_found_html`: 없는 주소 안내 `docs/404.html`. `wrangler.jsonc`의 `not_found_handling`이 404 상태로 내보냅니다. 검색에 넣지 않습니다(noindex, 표준 주소 없음, 사이트맵에 없음). 링크는 모두 `/`로 시작합니다.
- `build_lib.py`: 라이브러리 문서, 전체 사이트맵과 robots.txt. 문서 제목은 영문 제목과 한국어 이름이
  같은 말로 시작하면 한 번만 씁니다(`entry_title`).
- `build.py`: 홈 메타정보와 초기 제품 소개. 앱이 로드되면 같은 컨테이너를
  기존 홈페이지 화면으로 교체합니다. 방문자에게 숨긴 검색 전용 본문을 넣지 않습니다.
  이 개요는 홈의 조립 장면(첫 화면 그림)과 같은 자리·같은 문구·같은 어두운 바탕으로 그려, 본 화면으로 바뀔 때 번쩍이거나 꼬리말이 밀리지 않게 합니다(`site/build.py` `initial_home()`, 문구는 `site/catalog.py` `brand_copy()`가 `app/src/v9_tighten.js`에서 읽음). 검색용 h1은 그대로 한 개이고 화면에도 보입니다. 다른 화면(`/#list` 등)으로 바로 들어온 방문자에게만 화면이 그려지기 전 잠깐 가립니다.

`python3 tools/build_all.py`로 결과물을 만들고 `python3 tools/check.py`를
통과시킵니다. `tools/check_search.py`는 모든 검색 문서의 제목·설명·표준 주소,
사이트맵 일치와 내부 링크·제품 목록 범위를 확인합니다.

검색엔진 등록 주소는 `https://boltnote.net/`입니다.
`#home` 같은 화면 식별자는 개별 검색 문서 주소가 아닙니다.
Google·네이버에 제출할 사이트맵은 `/sitemap.xml` 하나입니다.
소유 확인 파일은 계속 보관합니다. 페이지를 추가했다고 수집·노출·순위가
확정되는 것은 아니며, 실제 검색어·노출·클릭과 색인 상태는 각 콘솔에서 확인합니다.

공개 본문은 한국어 제품명, 영문 BOM 표기, 적용 규격을 자연스럽게 연결합니다.
키워드 나열, 지역만 바꾼 중복 페이지, 확인되지 않은 공급·서류 약속,
가격·리뷰·재고를 지어낸 구조화 데이터를 추가하지 않습니다.


## 영문 사이트 (/en/, 대표 요청 2026-11-18)
- `/tables/`·`/products/`·`/lib/`의 모든 쪽은 같은 경로의 영문 짝이 `/en/` 아래에 있다 (예: `/tables/clevis-pin` ↔ `/en/tables/clevis-pin`). 홈의 영문 짝은 `/en/`이다.
- 만드는 곳: `site/build_en_site.py` (영문 틀) + `site/en/*.json` (번역 자료: lib.json·products.json·tables.json·guide.json). 번역 자료는 한국어 원문을 옮긴 것이다. 한국어 원문(`site/lib.json`, `app/src/ea_catdata.js`, `tools/t2/records`)을 바꾸면 해당 번역 자료도 같이 고쳐야 한다. 빠진 문장이 있으면 빌드가 멈춘다.
- 머리의 KO·EN 전환(`@@EN@@`·`@@KO@@` 자리표시는 `build_lib.page()`가 바꾼다)과 `hreflang`은 각 쪽의 짝을 가리킨다. 사이트맵에 영문 쪽이 모두 들어 있다.
- 점검(`tools/check_search.py`): 한국어·영문 쪽이 일대일이고, 영문 쪽에 한글(브랜드 이름 괄호·`lang="ko"` 링크 제외)이 남지 않는다.
- 영문 쪽도 규칙은 같다: 재고·가격·납기 약속, 후기·인증, 회사·출처 사이트 이름 없음. 납품은 국내, 견적은 원화(KRW).


## Transition 광고 자리 (대표 요청 2026-11-19)
- 원본: `site/tr-ad/` (`tr-ad.css`, `tr-ad.js`, `img/*`). 대표가 준 패키지(boltnote-ads.zip) 그대로이고, 문안·그림·링크는 Transition 쪽이 정한다. 문구를 여기서 고치지 않는다. 빌드(`site/build_brand.py`)가 `docs/assets/tr-ad/`로 복사한다 (그림은 같은 폴더에 평평하게).
- 자리: A `inline`(본문 끝, 견적 단추 다음) · B `side`(오른쪽 칸 맨 아래, 1023px 이하에서 숨김) · C `foot`(문의 띠 `bn-strip` 다음, `<footer>` 바로 위). 규격표·제품 안내·규격 사전 낱장은 A·B·C, 모음 쪽과 홈은 C만. 빈 상자는 `site/build_lib.py`의 `ad_slot()`이 만든다.
- 한국어 쪽에서만: 머리의 `TRAD`(css·js 두 줄)는 `lang == "ko"`인 색인 쪽과 홈에만 들어간다. 영문(`/en/`)·404·관리 화면에는 상자도 파일도 없다. `tr-ad.js`도 `/en/`에서는 스스로 멈춘다.
- 홈 앱(`app/base.html` 바닥글 위)의 띠는 홈과 읽는 화면(제품·사전·노트·소개 등)에서만 보이게 `app/src/zzzzzzzzzzzz_trad.css`가 `body[data-route]`로 제한한다. 견적함·Sales·견적·BOM·주문·품목 설정 화면에서는 숨는다.
- 하지 않는 것: 팝업·고정 띠·화면을 가리는 창, 쿠키·저장소·외부 요청, 광고 눌림을 우리 문의 집계에 더하는 것, 견적 단추보다 위에 두는 것. 링크는 새 창 + `rel="sponsored noopener"` + utm(`utm_content=<자리>-<광고>`)이다.
- 창간호 50부가 마감되면 `site/tr-ad/tr-ad.js` 맨 위 `PRINT_ON`을 `false`로 바꾼다 (Transition 쪽이 알려 준다).
- 점검: `tools/check_search.py`(자리 구성·영문 없음·견적 안내가 먼저), `worker/tests/browser.py` `check_trad`(PC·핸드폰 화면, 앱의 견적 화면에서 띠 숨김).
- 2026-11-19 확대 (대표: 볼트노트 자체 수입 기대는 0원, 주력은 Transition 매거진이라 광고를 키운다. 팝업·화면 가림 없이): 낱장은 **표·핵심 사항 바로 아래 작은 한 줄 띠(`tr-ad-mid`, `data-slot="foot"`)**가 하나 더 들어가고, 홈은 제품 목록 다음에 카드 한 장(`app/src/v7_ia.js`의 `.bn-trad`, 화면을 그린 뒤 `V.after.home`이 `trAdFill()`을 부른다), 모음 쪽(`/tables/`·`/products/`·`/lib/`·제품 분류)은 위쪽에 카드 하나와 바닥 띠가 있다. 볼트노트 쪽 보정 CSS는 `site/tr-ad/bn-ad.css`(Transition 원본 `tr-ad.css`는 고치지 않는다).
