# 검색용 페이지 관리

홈과 제품·라이브러리 문서는 자바스크립트 실행 전에도 본문을 제공합니다.
제품 구매 안내는 기존 공개 카탈로그의 품목·표기·주의사항으로 만들며,
재고나 판매 가격을 확정하는 페이지가 아닙니다.

- `catalog.py`: 공개 카탈로그 읽기, 공통 주소·홈 메타정보, 설명문 80자 이내 발췌.
- `product-paths.json`: 카탈로그 ID → 고정 주소. 이름 변경 시에도 주소를 유지합니다.
  새 품목을 추가하면 중복되지 않는 경로를 함께 넣습니다. 경로를 바꿔야 하면
  기존 주소의 영구 리디렉션과 사이트맵·링크 변경을 같은 작업에 포함합니다.
- `build_products.py`: 제품별 구매 안내와 제품군·전체 목록.
- `build_products.py`의 `SEARCH_META`: 서치어드바이저 검색어를 보고 제목·설명(80자 이내)·"다른 이름·검색어"를
  손본 품목만 적습니다. 값은 카탈로그의 품목명·`kw` 별칭·안내 문구에서만 가져옵니다. 없는 품목은 공통 양식을 씁니다.
- 정적 페이지의 끝(꼬리말 앞)에는 볼트노트 띠(`build_lib.py` `brand_strip`)가 붙습니다: 「볼트는, 볼트노트.」, 리드 한 줄, 「BOM·RFQ 보내기」(`/#list`)와 「카카오톡으로 문의」(채널 주소가 있을 때만). 검색으로 들어온 방문자는 홈을 보지 않기 때문입니다. 문구는 홈과 같은 것만 쓰고(`catalog.py` `brand_copy`), 재고·가격·납기를 적지 않습니다. `check_search.py`가 모든 정적 페이지에 두 링크가 있는지 봅니다.
- `build_lib.py` `not_found_html`: 없는 주소 안내 `docs/404.html`. `wrangler.jsonc`의 `not_found_handling`이 404 상태로 내보냅니다. 검색에 넣지 않습니다(noindex, 표준 주소 없음, 사이트맵에 없음). 링크는 모두 `/`로 시작합니다.
- `build_lib.py`: 라이브러리 문서, 전체 사이트맵과 robots.txt. 문서 제목은 영문 제목과 한국어 이름이
  같은 말로 시작하면 한 번만 씁니다(`entry_title`).
- `build.py`: 홈 메타정보와 초기 제품 소개. 앱이 로드되면 같은 컨테이너를
  기존 홈페이지 화면으로 교체합니다. 방문자에게 숨긴 검색 전용 본문을 넣지 않습니다.
  이 개요는 홈의 조립 장면(첫 화면 그림)과 같은 자리·같은 문구·같은 어두운 바탕으로 그려, 본 화면으로 바뀔 때 번쩍이거나 꼬리말이 밀리지 않게 합니다(`site/build.py` `initial_home()`, 문구는 `site/catalog.py` `brand_copy()`가 `app/src/v9_tighten.js`에서 읽음). 검색용 h1은 그대로 한 개이고 화면에도 보입니다. 다른 화면(`/#list` 등)으로 바로 들어온 방문자에게만 화면이 그려지기 전 잠깐 가립니다.

`python3 tools/build_all.py`로 결과물을 만들고 `python3 tools/check.py`를
통과시킵니다. `tools/check_search.py`는 모든 검색 문서의 제목·설명·표준 주소,
사이트맵 일치와 내부 링크·제품 목록 범위를 확인합니다.

검색엔진 등록 주소는 `https://boltnote.boltnote.workers.dev/`입니다.
`#home` 같은 화면 식별자는 개별 검색 문서 주소가 아닙니다.
Google·네이버에 제출할 사이트맵은 `/sitemap.xml` 하나입니다.
소유 확인 파일은 계속 보관합니다. 페이지를 추가했다고 수집·노출·순위가
확정되는 것은 아니며, 실제 검색어·노출·클릭과 색인 상태는 각 콘솔에서 확인합니다.

공개 본문은 한국어 제품명, 영문 BOM 표기, 적용 규격을 자연스럽게 연결합니다.
키워드 나열, 지역만 바꾼 중복 페이지, 확인되지 않은 공급·서류 약속,
가격·리뷰·재고를 지어낸 구조화 데이터를 추가하지 않습니다.
