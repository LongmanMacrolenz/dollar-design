# 볼트노트 견적 관리 연결

관리 화면: https://boltnote.boltnote.workers.dev/admin

공개 홈페이지는 그대로 사용할 수 있습니다. 메일은 비밀정보를 설정하기 전에는 수집하거나 보내지 않습니다. 메일 주소와 권한 승인만으로 네이버 계정 로그인이 완료되지는 않습니다.

## 최초 설정 (계정 소유자)

1. 네이버 메일 설정에서 **IMAP/SMTP 사용**을 켭니다. 계정 보안 설정의 2단계 인증과 외부 앱 비밀번호 발급 안내를 확인합니다. 이 계정은 `a8wlhg942@naver.com`으로 고정되어 있습니다. IMAP `imap.naver.com:993`, SMTP `smtp.naver.com:465`, 모두 TLS 연결입니다.
2. Cloudflare 대시보드 → Workers & Pages → **boltnote** → Settings → Variables and Secrets에서 아래 두 값을 **Secret**으로 등록하고 적용합니다. 채팅·GitHub·공개 화면에 입력하지 않습니다.
   - `PROCUREMENT_ADMIN_KEY`: 비밀번호 관리자에서 만든 32자 이상의 무작위 관리자 비밀키. 네이버 계정 비밀번호와 다르게 만듭니다.
   - `NAVER_APP_PASSWORD`: 네이버가 외부 메일 앱용으로 발급한 비밀번호. 관리자 로그인 창에는 넣지 않습니다.
3. `/admin`에 접속해 **관리자 비밀키**로 연결합니다. 키는 현재 탭의 sessionStorage에만 보관하며 잠금으로 삭제합니다. 공용 기기에서는 사용 후 잠급니다.
4. **메일 수집**을 눌러 상태가 `connected`인지 확인합니다. 처음에는 최근 30일 받은편지함의 읽지 않은 메일 중 제목에 `견적`, `RFQ`, `quote`, `quotation`이 있는 메일을 가져옵니다. 이후에는 신규 UID를 읽음 여부와 무관하게 5분마다 확인합니다. `BODY.PEEK`를 사용해 읽음 상태를 바꾸지 않습니다. 한 번에 최대 25개를 점검하므로 다음 주기에 이어서 처리합니다.
5. 공급처·원가 설정에서 공식 견적 연락처, 무료 배송을 포함한 확인된 운송비, 해외 환율·출처·기준일을 입력합니다. 한국볼트·화신볼트는 정확한 홈페이지를 먼저 등록합니다. 연락처가 확인되지 않은 회사에는 발송할 수 없습니다.

자동화는 실제 메일 수집 성공과 본인 수신 테스트로 확인합니다. `NAVER_AUTH_REJECTED`는 네이버 설정·앱 비밀번호를, 연결 오류는 계정 외부접속 허용과 네이버 연결 상태를 확인하세요. 설정 값이나 비밀번호는 오류 화면·로그에 출력하지 않습니다.

`IMAP_UIDVALIDITY_MISSING`는 로그인 이후 메일함 식별 정보를 읽지 못한 상태입니다. 앱 비밀번호 오류와 구분합니다. 서버가 `SELECT INBOX`에 식별 정보를 생략하면 `STATUS "INBOX" (UIDVALIDITY)`로 다시 확인합니다. 식별 값이 없거나 유효한 32비트 양수가 아니면 기존 수집 기록을 유지하고 중단합니다. 관리자 상단에는 설정 완료·수집 확인 전·수집 성공·수집 오류를 구분하고, 실패한 수집 직후에도 최신 상태 코드를 표시합니다. 성공 시각은 한국 시간입니다.

## 실제 업무 흐름

### 고객 BOM 자동 조달

1. 견적/BOM 메일의 XLSX 및 UTF-8 CSV·TSV·TXT 첨부 또는 머리글·수량이 있는 본문 표를 읽습니다. Excel 표를 머리글과 함께 복사하거나 관리자에서 XLSX·CSV·TSV를 불러올 수도 있습니다. 기존 홈페이지의 표 읽기 코드를 `tools/build_bom_reader.mjs`로 Worker에 함께 빌드합니다. 행 번호·원문·비고를 보존하며 수량 오류·미인식 행을 조용히 버리지 않습니다.
2. 명시된 제조사 품번은 정확히 대조하고 고객 내부 품번과 구분합니다. 품목의 규격·호칭·나사 계열/피치/공차·길이·재질/등급·표면처리를 구분합니다. 미지정 값은 확인 대상으로 남깁니다. NACE/사워, 저온·충격, 경도, 히트/로트, 코팅, PMI/입회/제출문서, 원산지/AVL, SET 구성, 대체 금지와 기타 특기사항을 요건별로 묶습니다. 등급 이름만으로 NACE 적합성·시험 결과를 선언하지 않습니다. 자동 인식하지 못하는 값은 고객 원본 대조 입력란에 명시할 수 있습니다.
3. **공급처·원가 설정**에서 공식 견적 이메일·연락처 확인·자동 문의 대상을 등록합니다. 대표가 승인한 자동 문의 흐름은 기본 켜짐이며 설정에서 중지할 수 있습니다. 등록된 공급처가 해당 특수요건을 충족한다고 가정하지 않고, RFQ 본문과 검토용 C&D CSV로 요건별 제시값·차이·문서/페이지/로트 근거를 요청합니다. 고객 이름/이메일과 조달 원가·가산율은 공급처 문의에 넣지 않습니다. 연락처가 없으면 발송하지 않습니다. 메일 Secret이 없으면 초안만 만듭니다.
4. 동일 요청·동일 BOM/공통 요건/문서 개정·동일 공급처 연락처의 문의는 한 번만 생성합니다. 반복 실행이나 문서의 검토 완료 표시만으로 재발송하지 않습니다. 요구조건 변경은 새로운 문의를 만들며 기존 요건별 답변·확인을 해제합니다. 전송 전 조건을 재확인하고, 실패·접수 불명확을 자동 재시도하지 않습니다.
5. 회신은 BNQ 제목 또는 등록된 공급처 주소와 outgoing Message-ID/In-Reply-To/References로 연결합니다. 연결되지 않은 등록 공급처의 견적은 새 고객 BOM으로 처리하거나 다른 공급처에 전달하지 않습니다. 발신자 진위와 원문을 검토한 뒤 조건을 등록합니다. 웹 검색은 정확한 고객 사양과 공식 공급처 도메인을 사용한 후보 검색 링크입니다. 실제 품번·공급 가능 여부·납기·서류는 공급처 회신으로 확인합니다.
6. 각 요건에 **제시값·C/D 판정·근거**가 필요합니다. B7M/B7, 나사 피치, 3.1/2.2 등 핵심값의 차이는 편차(D)이며 체크박스를 모두 눌러도 고객 견적을 만들 수 없습니다. 미회신·미검토 문서는 확인(C)으로 남깁니다. 도면을 참조하면서 원본/개정이 없으면 준수 처리하지 않습니다. 고객이 대체를 서면 승인하면 승인 문서를 검토 목록에 기록하고 고객 요구사양을 개정한 뒤 새 조건으로 다시 확인합니다. 소프트웨어가 동등성이나 특수요건 준수를 임의 승인하지 않습니다.
7. 모든 요건과 상업 조건을 확인한 후보만 기존 원가 × 1.20 조합·고객 견적 작성으로 이어집니다. C&D는 관리자에서 UTF-8 CSV로 내려받을 수 있습니다. 이 CSV의 회신 근거는 내부 검토용이며 공급처 이름/매입 정보가 있는 원문을 고객에게 그대로 전달하지 않습니다. 고객 견적 발송은 최종 검토를 유지합니다.

XLSX는 모든 시트의 셀 값을 읽되 수식·매크로·외부 연결을 실행하지 않습니다. RFQ 머리글 위 메타데이터의 기술 조건을 보존하고 고객 연락처는 제외합니다. 수식·미인식 시트는 원본 대조 대상으로 남기며 압축 크기·행/열·셀 수를 제한합니다. PDF·구형 XLS·도면 첨부는 문서 목록과 EML 원본으로 보존하고 **원본 검토 전 준수 처리하지 않습니다**. Excel에서는 표를 복사하거나 CSV UTF-8로 저장합니다. PDF의 OCR 결과나 유료 규격 전문을 자동으로 근거 삼지 않습니다. 참조만 있고 받지 못한 문서도 검토 목록에 등록해 확인 대상으로 남깁니다. 메일 수신·SMTP 실제 연결은 별도 설정이며 자동화 테스트는 합성 IMAP/SMTP와 example.com 주소만 사용합니다.

- 받은 견적 메일 → XLSX/CSV의 품목·수량·비고 자동 분석 → 고객 이메일·특수요건·문서 원본 확인. 첨부파일은 네이버 메일 또는 EML 원본 다운로드로 확인합니다. Excel 표는 머리글과 함께 복사해 붙일 수 있습니다. 첨부문서의 지시를 실행하거나 금액·사양을 자동 확정하지 않습니다.
- 공식 상품 페이지의 JSON-LD 가격은 **후보**로 읽습니다. 사이트가 접속·자동조회·상품 데이터 제공을 제한하면 직접 확인한 정보를 입력합니다. 계정 로그인, CAPTCHA 우회, 무단 주문은 하지 않습니다. 일반 상품 페이지에 가격이 없다는 이유로 숫자를 만들지 않습니다.
- 나사산이 없는 핀·와셔처럼 해당하지 않는 사양 확인 항목은 품목별로 제외할 수 있습니다. 서류·납기 조건은 항상 확인합니다. 고객이 서류를 요청하면 공급처의 제공 조건을 입력해야 견적을 만들 수 있습니다. 조건 입력 중 품목이나 공급처를 바꾸면 기존 확인을 해제합니다. 저장된 고객 품목·수량·사양·요청 서류·확인 항목이 바뀌면 해당 공급 조건의 확인 상태도 서버에서 해제하며, 다시 확인하기 전에는 견적을 만들 수 없습니다.
- 공급처 문의 초안 → 수신처와 내용을 검토해 발송 → 공급처 회신·견적서를 근거로 사양/포장/최소 주문량/공급 수량/납기/서류/유효기간 확인.
- 배송비를 포함한 공급처 조합 → 확인된 조달 원가 × **1.20** → 원 단위 판매 단가 올림 → 부가세 10% 별도 계산. 해외 통관 비용과 근거를 입력해야 반영됩니다. 통관율이나 환율을 추정하지 않습니다.
- 환율 기준일은 한국 날짜로 입력합니다. 날짜만 입력한 값은 한국 시간의 해당 날짜 시작으로 해석하며, 미래 기준일이나 존재하지 않는 날짜는 사용할 수 없습니다. 시간대가 포함된 API 기준 일시는 그 시각을 유지합니다.
- 고객 견적서와 한국어 PDF 검토 → 고객 발송. 공급처·매입가·가산율은 고객 문서에 포함하지 않습니다. 고객 사양이나 공급 조건 변경 이후에는 견적을 다시 작성해야 합니다.

개당 가격과 포장당 가격을 구분합니다. 요청보다 큰 최소 주문량·포장 수량은 매입 원가에 전부 반영합니다. 같은 공급처 품번이 여러 줄이면 전체 매입 수량이 확인된 공급 수량을 넘지 않게 확인합니다. 배송비는 공급처별 한 번 합산하므로 해당 견적의 배송지·묶음 배송 조건까지 확인해야 합니다.

`accepted`는 네이버 SMTP 서버가 접수했다는 뜻이며 고객의 수신 확인이 아닙니다. `delivery_unknown`은 접수 여부를 판단할 수 없어 **자동 재발송하지 않습니다**. 네이버에서 발송·수신 여부를 직접 확인하세요. 명확한 `failed`만 원인을 해결하고 검토한 뒤 재시도합니다. 발송 대기 메일은 자동 전송 전에 현재 조건을 다시 검사합니다.

8MB 초과 메일은 원본을 자동 내려받지 않고 수동 확인 표시를 남깁니다. 저장된 원본·연락처·가격·메일 내용은 SQLite Durable Object에 비공개로 보관합니다. 홈페이지 정적 파일과 GitHub에는 들어가지 않습니다. 이 버전은 주문·결제·입고 확정 기능을 제공하지 않습니다.

## 개발·배포

Node 24+, Python 3.11+. `npm ci`, `python3 tools/build_all.py`, `python3 tools/check.py`, `npm run check:worker`.

Cloudflare의 Git 연결이 `main` 병합 후 `npx wrangler deploy`로 배포합니다. 최초 배포는 `PROCUREMENT` SQLite Durable Object를 `procurement-v1` migration으로 생성합니다. 실제 고객 데이터를 이용한 테스트를 하지 않습니다. 브랜치·PR·CI를 통과시킨 뒤 병합합니다. `keep_vars: true`로 대시보드 설정값을 코드 배포 시 보존합니다. Variable도 서버에 전달되지만 비밀번호·관리자 키는 Secret으로 보관합니다. Secret은 배포 설정에서 보존하며 wrangler.jsonc에 값으로 적지 않습니다.

로컬 메일 연결을 검증할 때만 `.dev.vars`에 테스트용 비밀정보를 넣습니다(파일은 git이 무시). 테스트는 합성 가격·example.com 주소와 가짜 소켓을 사용하며 실제 메일을 발송하지 않습니다.

한국어 PDF 글꼴: Google Fonts 공식 Gothic A1 Regular, SIL Open Font License. `worker/assets/OFL.txt` 참조.
